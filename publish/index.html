AgenticApps · spec-first workflow

Run a change · Linear → shipped

Every code-touching task follows the same eight moves. The OpenSpec CLI orchestrates the spec, Superpowers builds it, Linear says what's next — and it runs the same on claude, codex, opencode & pi.

Where you type it → ⌘ in agent a /opsx: slash command ▸ CLI an openspec verb ⚙ script a gate shell script 🔒 auto enforced, no typing
You stay in one agent session the whole time — it runs the ▸ and ⚙ commands for you. The only separate actors are the plan-review agents (2b), which run headless and hand back a file.

Plan the change · Linear → validated spec
0

Pick the Linear issue

in Linear
Grab the ticket you're working. Note its ID — e.g. AGE-123 — you'll reference it in the change. Linear owns priority; there's no sync.
1

Propose

⌘ in agent›/opsx:propose "idea" → runs openspec new change
The agent scaffolds the change folder and authors it: proposal.md (+ Linear: AGE-123) · design.md · the spec delta · tasks.md. State the delta before writing code.
2

Validate

▸ CLI›openspec validate --all
The agent runs it for you (or you run it in a terminal — same command). Green = every requirement has a scenario. A structural lint, not a review.
2b

Plan-review

⚙ script›run-plan-review.sh <slug>
One command spawns ≥2 other-vendor agents headless (gemini -p …, codex exec … </dev/null) to critique the proposal + spec delta → changes/<slug>/REVIEWS.md. You don't switch into them — they run and hand back a file. Read it, fix, re-validate.
🔒

Gate — no code edits yet

🔒 automatic · hook + CI
validate GREEN + REVIEWS.md ≥ 2
You don't run this — the hook + CI enforce it. It blocks on one thing: openspec validate --all not green.
Build the change
3

Implement

⌘ in agent›/opsx:apply + TDD
Superpowers: writing-plans → RED (failing test first) → GREEN. Conditional gates fire by what you touch: security always · db-sentinel (SQL/RLS) · design + qa (UI).
4

Code-review + verify

⌘ in agentthe diff
An independent reviewer critiques the implementation diff, then verification-before-completion confirms the diff satisfies the tasks and the spec delta.
Land the change
5

Archive

▸ CLI›openspec archive <slug> -y
Folds the delta into specs/ — now current truth — and moves the change to changes/archive/.
6

Ship

▸ CLI / yourelease
Conventional commit · PR · changelog · version · close the Linear issue. archive ≠ ship — OpenSpec never commits, PRs, or tags.
