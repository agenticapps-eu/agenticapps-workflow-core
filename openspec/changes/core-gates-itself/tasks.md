## 4. The pre-commit floor

- [x] 4.1 Write `tools/install-core-git-hooks.sh`, resolving the destination with `git rev-parse --git-path hooks` and writing a `pre-commit` that `exec`s core's working-tree gate with `--pre-commit`. Never write a literal `.git/hooks/` path: in a linked worktree `.git` is a file and that path does not exist.
- [x] 4.2 Do **not** refuse merely because `core.hooksPath` is set. Verified directly: `git rev-parse --git-path hooks` honors it, returning `.githooks` when configured — so the resolver already targets the directory git reads, and a refusal would be a false positive every time, including when the setting names the default. Refuse only when the resolved hooks directory lies inside the working tree, since installing there writes into tracked repository content.
- [x] 4.3 Implement the four marker outcomes explicitly: absent → install; marked and current → no-op, reported as such; marked and stale → update in place, reported as an upgrade; unmarked → refuse, report what was found, exit non-zero. Byte equality is deliberately not the test — it would make every revised hook permanently foreign and the gate unadvanceable.
- [x] 4.4 Run it in this checkout and confirm the resolved hooks path now holds an executable `pre-commit`.
- [x] 4.5 Test all seven installer paths in throwaway clones under `$TMPDIR`: fresh, second run, stale-marked, marked-but-non-executable, foreign-unmarked, `core.hooksPath` outside the tree (installs), and `core.hooksPath` inside the tree (refuses). Do not plant a foreign hook in the real checkout.
- [x] 4.5a **Test the in-tree case with a directory that does not exist**, not only an existing one. 4.5 as written passed while the guard was broken: it only ever pointed `core.hooksPath` at a directory already on disk, and `canon()` can only resolve a path it can `cd` into. With `core.hooksPath=deep/not/there` — directory and parent both absent — canonicalisation fell back to the parent, that was absent too, and the result was `/there`, which is not inside the tree. The installer created the missing parents and wrote the hook into the working tree, printing `installed` and exiting 0. Found by the Stage-2 review (6.5), reproduced, fixed by canonicalising the deepest existing ancestor. Cover both the outside-the-tree deep-missing case (installs) and the inside-the-tree deep-missing case (refuses).
